ZWT FINANCE UI SYSTEM · DENSITY B

财务工作台组件体系

不是重写 Ant Design，而是在它上面建立稳定的财务业务组合层。所有模块共享同一套密度、页面骨架、台账、详情抽屉、格式化和状态反馈。

推荐组织方式 Ant Design 基础控件 + ZWT 业务组合组件 + 模块配置。先服务当前单体前端，暂不拆独立 npm 包。

四条固定设计原则

以后新增页面只选模板和填业务配置，不再重新决定视觉。

01 · DENSITY数字和记录优先

默认 14px 正文、32px 控件、36px 台账行，1080p 首屏可见更多数据。

02 · LAYOUT台账始终全宽

详情使用覆盖式抽屉，不再挤压表格；无数据和未选择状态不预留空列。

03 · TYPE业务页统一无衬线

大标题收敛到 24–26px；金额、编号和日期使用等宽数字，提升纵向核对。

04 · COLOR颜色只表达状态

保留单一棕色操作强调；绿、橙、红仅用于成功、待复核和异常。

建议代码边界

业务规则继续留在模块内；共享层只负责稳定 UI 与展示语义。

src/
├─ app/
│  ├─ AppShell.tsx
│  └─ theme.ts
├─ ui/
│  ├─ tokens/       颜色、字号、密度、间距
│  ├─ components/   财务语义小组件
│  ├─ patterns/     台账、抽屉、表单组合
│  ├─ formatters/   金额、日期、编号
│  └─ index.ts
└─ modules/
   ├─ wht/          列定义、状态映射、流程规则
   └─ tax-invoice/  列定义、状态映射、税票规则
  1. 不包装所有 Ant Design 控件：Button、Input、Select 仍直接使用，避免组件层变厚。
  2. 模块只传配置：标题、筛选项、列定义、抽屉内容、允许动作和状态映射。
  3. 财务数字统一：金额右对齐并使用等宽数字；精度由业务 formatter 明确声明。
  4. 默认密度固定：32px 控件、36px 行高、24–26px 页面标题，不允许页面自行放大。
  5. 抽屉不改变表格宽度：打开详情只覆盖右侧；关闭后恢复原行焦点和滚动位置。
  6. 组件必须有测试样例：至少覆盖空数据、加载、错误、长泰文、长编号和权限禁用状态。
