# 系统架构基线

## 模块边界

系统使用一个独立 PostgreSQL 15 数据库 `zwt_finance`，按 schema 隔离：

- `core`：用户、角色、共享业务主体、签名版本、文件元数据。
- `wht`：WHT 任务、编号计数器、开具数据和历史导入。
- `tax_invoice`：TAX INV、报关单、商品行、汇率快照。
- `audit`：不可覆盖的关键操作和版本事件。

模块只能通过 Python 服务层或稳定 API 使用共享数据。WHT 和 TAX INV 不直接写对方
的业务表。BOI 数据库和旧 SQLite 均不在连接配置中。

## 前端扩展方式

`src/modules/registry.tsx` 是模块入口注册表。新模块提供页面组件、权限键、路由段和
导航元数据后即可进入统一外壳。设计令牌、国际化、上传、审计和右侧详情检查器属于
平台能力，不在每个模块内复制。

数据库/API 字段使用英文，所有用户可见标签通过 `src/i18n/` 翻译。默认语言是简体
中文。泰文业务值必须带 `lang="th"`，字体顺序为 `TH SarabunPSK`、
`TH Sarabun New`、内置 `Sarabun`，正文相对字号为 `1.28em`、行高 `1.2`。

## WHT 编号不变量

- 正常：任务编号 `ZWTYYYYMMNNN`，册码 `YYYYMM`。
- 补开：任务编号 `ZWTYYYYMMBKRSS`（`R` 为第几次补开，`SS` 为本次第几份），
  例如 `ZWT202606BK101`；册码为 `YYMMBKR`，例如 `2606BK1`。
- 正式编号只在批准事务中分配。计数器行使用 `SELECT ... FOR UPDATE` 锁定，
  `wht.tasks.task_no` 另有数据库唯一约束。
- 草稿不占号；正式号不得由浏览器提交。

## TAX INV 已锁定规则

- 开票日期取报关单提交日期。
- 发票编号格式为 `ZWT-IVYYYYMMDD-NN`，日期段取开票日期；正式号只在批准事务中
  分配，浏览器不能指定或修改。
- `invoice_date`、`exchange_target_date`、`exchange_rate_date` 独立保存。汇率继续
  执行旧系统既有逻辑，包括周末/无报价日最多回溯 9 天。
- 单张发票常规不超过 18 条商品。数据库允许保留超过 18 行的待处理数据，但当前
  正式模板在超过 18 行时禁止批准，避免静默截断。
- 旧 `Sample.xlsx` 没有独立报关提交日期时，只把旧 FX Date 作为迁移回退值，并
  设置低置信度警示；复核人必须显式接受警示才能批准。
- 已批准或已出具税票只能通过“作废”流程失效，原编号不回收。更正单通过
  `correction_of_id` 关联原作废记录，复制商品与客户数据重新复核，批准时取得
  当日下一个新编号；所有动作记录原因、操作者、时间和版本。

## 文件与签名

- 单文件业务上限 20 MiB，后端逐文件再次校验。
- 双文件接口的 Caddy 请求体上限为 42 MiB。
- 10 文件 BOM 接口的 Caddy 请求体上限为 202 MiB。
- 签名图片按不可变版本保存，正式文件记录使用的签名版本与 SHA-256。
- WHT 与 TAX INV Excel 正式文件分别从经批准的外部 `.xlsx` 模板生成。
- WHT PDF 正式文件使用应用内置四联 PDF 底版及内置 Sarabun 字体生成，不调用
  Office 或 Excel COM，适用于没有交互式桌面会话的低权限 WinSW 服务账号。
- 签名原图和生成的 Excel/PDF 位于独立附件根目录，不写入 release 目录；发布切换
  不影响历史文件，附件与 PostgreSQL 数据库必须在同一备份批次中保留。
